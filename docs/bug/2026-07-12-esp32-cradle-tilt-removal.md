# 65 — 틸트 삭제로 무효화된 ESP32 크래들 (바텀갭 3.5 에 모듈 4.2 불가)

## 증상

keypad-17 브랜치 조립 전수검사 중 동일 관점으로 split(65)을 재검사(2026-07-12, 사용자 요청)한 결과, ESP32-C3 SuperMini 크래들이 **물리적으로 조립 불가** 상태였다.

## 원인 (근본)

크래들·모듈 배치(2026-07-07)는 **7.5° 틸트로 후방 바텀갭이 ~15mm** 라는 전제에서 설계됐다. 2026-07-10 2차에서 틸트를 삭제(`TILT_DEG=0`)하며 갭이 **균일 3.5** 가 됐는데, 크래들·모듈 검토가 누락된 채 방치됐다.

바텀갭 3.5 기준 수치 (pcbTop=0, bottomTop −5.1):

| 항목                           | z    | 판정                                                    |
| ------------------------------ | ---- | ------------------------------------------------------- |
| 모듈 USB 포함 전고 4.2 → top   | −0.9 | **PCB 하면(−1.6) 0.7 관통 — 삽입 자체 불가(4.2 > 3.5)** |
| 모듈 본체(쉴드 변종 3.4) → top | −1.7 | 소켓 바닥(−3.6) 대비 **1.9 관통**                       |
| 핫스왑 소켓 바닥(PCB −2.0)     | −3.6 | 슬롯 존 위 스위치 좌1(57,0)·우2(57,0·76,0)개            |
| 뷰어 GLB(5.3) → top            | +0.2 | PCB 를 뚫고 나옴(뷰어에서도 확인 가능)                  |
| 레일(2.8) top                  | −2.3 | PCB 와 0.7 — 레일만은 통과                              |

크래들을 다른 변으로 옮겨도 보드 깊이 22.82 ≫ 마진이라 스위치·소켓 존을 벗어날 수 없음 → **Z(바텀갭)가 유일한 레버.**

## 해결

`BOTTOM_GAP` 을 리터럴 3.5 에서 **제약 파생식**으로 교체 (`65/config/dimensions.ts`):

```
BOTTOM_GAP = HOTSWAP_SOCKET_BELOW_PCB 2.0 + ESP32_CLEARANCE_MARGIN 0.3
           + ESP32_MODULE.boardThickness 1.0 + ESP32_MODULE.bodyHeight 2.4 = 5.7
```

- 지배 제약 = 소켓 바닥 ↔ 모듈 본체(쉴드캔 변종 worst 2.4). USB 제약(G ≥ 4.5)은 자동 충족(USB 존 y ≥ 8.5 는 스위치-프리 마진 존).
- `ESP32_MODULE`·`HOTSWAP_SOCKET_BELOW_PCB` 상수 신설(치수 근거: docs/memory/cherry-mx-dimensions.md 소켓 ~1.8–2.0 → worst 2.0, keypad-17 과 동일 모듈 worst).
- smoke(`65/export/smoke.ts`)에 간섭 가드 3종(본체↔소켓 / USB↔PCB / 레일↔PCB) 추가 — 음수면 throw.
- 초기 검토는 베어 SoC(2.1) 기준 G=5.0 이었으나, keypad-17 에서 표준화한 쉴드 변종 worst(3.4) 기준으로 **5.7 확정**(5.0 이면 쉴드 변종에서 0.4 재간섭).

## 검증 (바텀갭 5.7, bottomTop −7.3)

- 소켓 바닥(−3.6) ↔ 본체 top(−3.9) = **+0.3** / PCB 하면(−1.6) ↔ USB top(−3.1) = **+1.5** / 레일 top(−4.5) = **+2.9**
- typecheck 0 · format clean · smoke ok(양측) · export: top 17.3 / plate 1.5 / bottom 7.2 (좌 146.4·우 165.4 — A1 mini 내) · vite build 통과
- 스택 16.6 → **18.8**. PCB(발주 예정분)·plate 무변경 호환, **재출력은 top·bottom 만**.

## 재발 방지

- 전제(틸트)가 삭제되면 그 전제 위에 세운 결정(크래들 위치·갭)을 **전수 재검토**한다. 삭제 커밋에 의존 항목 체크리스트를 남긴다.
- 부품을 갭에 넣는 결정은 갭에 들어가는 모든 것(레일+모듈+소켓+솔더)의 스택으로 검증한다(keypad-17 동일 교훈).

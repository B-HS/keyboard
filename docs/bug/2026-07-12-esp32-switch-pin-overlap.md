# keypad-17 — ESP32 모듈 본체 ↔ 스위치 핀 간섭 (바텀갭 7.0 결정의 검증 누락)

## 증상

- 뷰어에서 크래들에 안착한 ESP32 모듈(검정 슬랩)과 row0 스위치 하단(핀)이 겹쳐 보임. **사용자 발견.**
- 크래들은 케이스 뒷변 중앙(slot y +6.0 ~ −16.82, x 28.95~47.25). row0 스위치 2개(x 28.575, 47.625 / y −9.525)의 하우징·핀 클러스터가 모듈 바로 위에 위치.

## 원인 (근본)

바텀갭 6→7.0 결정(design-decisions #3)이 **크래들 레일 상단(−9.2) vs 핀 끝(−8.3)만 검증**하고, 레일 안에 들어가는 **모듈 본체 높이와 핸드와이어 솔더 여유를 계산에서 누락**했다.

바텀갭 7.0 기준 수치 (plateTop=0, bottomTop −12.0):

| 항목                        | z      | 비고                                        |
| --------------------------- | ------ | ------------------------------------------- |
| 핀 끝                       | −8.3   | 하우징 −5.0 − 핀 3.3                        |
| 솔더·와이어 최저점          | ≈ −9.5 | 핀 끝 − 1.2 (핸드와이어 필수 여유)          |
| 모듈 본체 top (베어 SoC)    | ≈ −9.9 | PCB 1.0 + SoC ≈0.9~1.1 → 여유 0.4뿐         |
| 모듈 본체 top (쉴드캔 변종) | ≈ −8.6 | PCB 1.0 + 쉴드 2.4 → **솔더 기준 0.9 관통** |
| 뷰어 박스(구 3.2 균일) top  | −8.8   | 핀과 0.5 — 렌더 겹침의 직접 원인            |

크래들을 다른 변으로 옮겨도 해결 불가: 보드 깊이 22.82 ≫ margin 6 이라 어느 변에서도 최외곽 행/열 스위치 밑으로 들어간다. **Z(바텀갭)가 유일한 레버.**

## 해결

1. **`BOTTOM_GAP` 을 리터럴에서 제약 파생식으로 교체** (`config/dimensions.ts`):
   `BOTTOM_GAP = 핀 3.3 + 솔더여유 1.2 + 모듈최악고(PCB 1.0 + 본체 2.4) + 마진 1.1 = 9.0`
   모듈 최악고는 쉴드캔 변종 기준(`ESP32_MODULE.bodyHeight 2.4`). 마진은 최초 0.6으로 잡았다가 **사용자 요청("살짝 더")으로 1.1 로 상향**. 전고 18.5 → **20.5**.
2. **`ESP32_MODULE` 상수 신설** — 보드 18.0×22.52, PCB 1.0, 본체 16×12×2.4, USB-C 9.0×7.35×3.2. `ESP32_CRADLE` 의 보드 치수 중복 제거(참조로 통일).
3. **뷰어 모형을 실물 외형으로 교체** (`viewer/case-meshes.ts`): 균일 3.2 박스 → PCB + 본체 + USB 3박스. USB는 보드 뒷단(케이스 뒷변, 스위치 없는 margin 존)에 위치 — 렌더가 실제 간섭 여부를 그대로 보여줌.
4. **smoke 에 간섭 가드 추가** (`export/smoke.ts`): 솔더최저↔본체top / 핀↔레일top / USB 전방 y 여유 3종을 출력하고 음수면 throw — 이후 치수 변경 시 CI(smoke)에서 자동 차단.

## 검증 (바텀갭 9.0, bottomTop −14.0)

- 솔더 최저(−9.5) ↔ 본체 top(−10.6) = **+1.1** / 핀(−8.3) ↔ 레일 top(−11.2) = **+2.9** / USB 전방 y 여유 **+1.03** (USB 존 y ≥ −1.5, row0 하우징 뒷변 −2.53)
- typecheck 0 · format clean · smoke ok · export: top 88.2×107.2×18.8 / plate ×1.5 / bottom ×14.0 (A1 mini 내) · vite build 통과
- 1:1 STL `keypad-17/export-out/fdm/` + 1/5 검증본 `fdm-mini/`(17.6×21.4) 생성 완료 — 바로 슬라이서에 올릴 수 있음.
- USB top −9.8 은 위에 스위치가 없는 margin 스트립 하부라 무간섭. 레일·립·슬롯은 bottomTop 상대치라 무변경 호환.

## 재발 방지

- 부품을 갭에 넣는 결정은 **그 갭에 들어가는 모든 것(레일+모듈+솔더+와이어)의 스택**으로 검증한다. 단일 부재만 보고 "근본 해결"로 기록하지 않는다.
- 뷰어 대용 모형은 실물 최대 외형을 반영한다(과소 모형은 거짓 안심을 만든다).

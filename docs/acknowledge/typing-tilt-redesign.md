# 타이핑 틸트(6도) 도입 — 검토안

> 상태: **폐기(2026-06-25)** — 뷰어에 6° 틸트를 실제 적용(쐐기 받침 + 내부 스택 6° 회전)해 Zen 65와 비교한 결과, **틸트를 넣으니 케이스가 너무 커져버려** 폐기. 평평한 v3 유지. 아래는 검토 기록(보존). 결론은 §6.
> 트리거(2026-06-25, 사용자):
> ① "하판이 스위치랑 너무 딱붙어있네" ② "일체형 상판이랑 PCB에 6도 정도 기울기 줄 수 있나? 맨위(펑션열)가 높아지고 스페이스바쪽을 낮추고" ③ "다만 CNC가 좌우벽을 각도 기준으로 구멍을 깎아낼 수 있냐가 문제이긴해".

## 1. 기하 (현재 v3 기준)

- 케이스 앞뒤 깊이(caseOutline.h) = **105.25mm**. 6도 틸트 → 앞뒤 높이차 = tan(6°)×105.25 = **11.06mm** (뒤=펑션열 높음, 앞=스페이스바 낮음).
- 현재 스택(전부 서로 평행한 평판, 2D 레이저컷): 일체형 상판 6.75 / 에어갭 벽 3.5 / PCB 1.6 / 바텀갭 벽 3.5 / 하판 3 = 18.35mm.
- 결착: M2 볼트 하단진입(하판 밑→위로 관통→보강판 플랜지 인서트). 좌우 아크릴 벽 스페이서(앞뒤 개방).

## 2. 리서치 결론 (출처 포함)

### 2.1 6도 각도 — 적정 (변경 근거 약함)

- 기계식 키보드 타이핑 앵글 표준 = **0~~7도(넓게 5~~11도)**, 5~7도가 가장 흔한 출고값. 7도가 OEM/타자기 유산의 사실상 업계 표준.
- **6도는 표준 범위 중간값.** ai03 **Equinox가 정확히 6도**(프론트 높이 7.25mm) 채택, Altair 7도.
- 손목 신전↑ → 수근관 압력↑(중립 1.9kPa→45° 4.0kPa). 6도는 신전을 과하게 키우지 않는 보수적 선택.
- 출처: whatgeek/mechanical-keyboard-typing-angle, keebs101, cannonkeys/equinox, PMC2649727.
- → **스펙에 '케이스 6도 + 프론트 끝 높이' 병기** 권장.

### 2.2 바텀갭 3.5mm("스위치랑 딱붙음") — 소켓 기준 OK

- Kailh/Cherry MX 핫스왑 소켓은 PCB 하면 아래 **약 1.8mm만 돌출**. 스위치 핀은 소켓 내부 접점에서 멈춰 **PCB를 추가 관통하지 않음**(솔더 마운트의 핀 3.3mm 돌출이 소켓 1.8mm로 대체).
- 바텀갭 3.5 − 소켓 1.8 = **1.7mm 여유**. 권장 클리어런스(3mm 권장/2mm 위험)를 소켓 돌출 기준으로 만족 → 정적으로 **충분**.
- 뷰어에서 "딱붙어" 보인 건 `silent_alpaca.wrl`이 풀 스위치(핀 길게 모델링)라 PCB 아래로 핀이 길게 내려와 보이기 때문. 실제 핫스왑은 핀이 소켓에 흡수됨.
- 단 USB 데몬보드·컨트롤러·JST 배선이 같은 3.5mm를 공유하면 국부적으로 빠듯 → 소켓 없는 키매트릭스 외곽 배치 또는 1.0mm 데몬보드.
- 출처: hilpcb/keyboard-pcb-layout, keeb.io Mill-Max, geekhack 104376, fastturnpcbs.

### 2.3 ★틸트 흡수면 — PCB↔하판 갭에서 주면 안 됨 (가장 중요)

- 6도를 PCB↔하판 갭에서 흡수하면 바텀갭이 **앞뒤 가변**이 되어 앞쪽(스페이스바) 모서리에서 갭이 3.5mm에서 크게 줄어 **소켓 1.8mm와 충돌**(최악 음수).
- → 틸트는 **하판 쐐기** 또는 **외부 발**에서만 흡수하고 **PCB↔하판은 반드시 평행 유지**. 그러면 클리어런스 문제와 틸트가 **완전히 분리**된다.

### 2.4 CNC 경사가공 — 사용자 우려가 정확함

- **레이저컷 = 빔이 표면에 항상 90° 입사 → 평판 2D 윤곽만.** 경사면·쐐기 두께·비스듬한 구멍 원리적으로 불가(별도 V-그루브/베벨 모듈 필요).
- **3축 CNC도 회전축이 없어** "각도 기준 비스듬한 볼트 구멍"을 그 자체로 못 깎음 → 좌우 벽을 6도로 들어주는 **전용 틸트 지그(쐐기 픽스처)** 고정 후 수직 드릴, 또는 **5축(고가)**.
- 통짜 쐐기 아크릴 블록 CNC = 두꺼운 스톡 폐기 + 아크릴 발열(눌어붙음)로 소량 제작에 비효율.
- 대안: **cast 아크릴 평판을 Weld-On 솔벤트 본딩으로 비스듬히 단차 적층** → 모재급 강도(24h ~1700psi)로 레이저컷 평판만으로 쐐기 구성 가능.
- 출처: eurolaser, golaserengraving, tirapid(3 vs 5축), hubs, dakingsrapid, daniellewethington/Weld-On.

## 3. 옵션 비교

### 옵션 A — 외부 틸트 발 / 쐐기 받침 (케이스 본체 무변경)

- **방법**: 18.35mm 평행 스택은 전부 그대로. 하판 밑에 앞 얇고 뒤 두꺼운 **별도 적층 아크릴 발**(또는 4점 범폰 높이차)을 달아 케이스째 6도. CannonKeys Stacked65(7장 평행 적층 + 별도 4층 아크릴 발), kissetfall stacked-cases(별도 5mm 스탠드 M2 체결) 방식.
- **레이저컷**: 100% 유지(본체 5장 + 발 모두 평판). 비스듬한 구멍 0.
- **장점**: 제작 파이프라인 무변경, 클리어런스와 완전 분리, 가역적(발 교체로 각도 조절). 가장 안전.
- **단점**: '상판/PCB가 케이스와 일체로 기운 일체감' 약함(받침 위 평평 케이스 외형). 풋프린트 뒤로 확장.

### 옵션 B — 쐐기 하판 (경사를 바닥 1장이 전담) ★ 1순위 추천

- **방법**: 상판·에어갭벽·PCB·바텀갭벽은 전부 현행 평행 평판 유지. **하판만** 윗면=스택 평행, 아랫면(책상 접지)=수평인 **쐐기**(앞 얇고 뒤 두꺼움, 두께차 ≈ 11.06mm). 바텀갭 3.5는 PCB에 평행 유지 → 클리어런스 불변. 결착 볼트는 스택에 직교 유지.
- **레이저컷**: 하판 1장만 비평판. **Weld-On 솔벤트 본딩으로 평판 단차 적층** 시 레이저컷 유지(모재급 강도). (통짜 CNC는 비효율로 비권장.)
- **장점**: 내부 스택·클리어런스·결착 모두 보존 + 케이스째 기운 일체감(발보다 우수). 비스듬한 볼트 구멍 회피.
- **단점**: 하판 두꺼워짐(뒤쪽)·무거워짐. 본딩 공정(정밀 단차 관리) 추가. 볼트 머리 안착면이 접지면 기준 6도 → 고무발/카운터보어로 흡수 필요(상세 설계 과제).

### 옵션 C — 쐐기 좌우 벽 (사용자 상상) — 비권장

- **방법**: 좌우 벽을 쐐기 단면으로 만들어 상판+PCB를 박스 안에서 6도 기울임. 하판은 평평. Lemokey L3(알루미늄 CNC 쐐기 바디 ~5°)의 아크릴 판.
- **레이저컷**: 상실 최대. 사용자가 우려한 **'각도 기준 비스듬한 볼트 구멍'이 바로 여기서 발생** → 레이저 불가, 3축은 지그 필수, 5축 고가.
- **단점**: 결착 재설계 강제(경사 볼트 or 경사 카운터싱크), 바텀갭이 틸트와 엉켜 앞쪽 충돌 검증 필요, 지그/CNC 비용. 소량 제작에 가장 비효율.

## 4. 추천

**1순위: 옵션 B(쐐기 하판) + Weld-On 솔벤트 본딩 단차 적층.**

- 제작 단순성(레이저컷 최대 유지) + 사용자 의도(케이스 일체로 기운 일체감)의 균형에서 최선. 내부 4레이어는 현행 평판 그대로 → 클리어런스(바텀갭 평행)·결착(M2 직교) 보존, 하판 1장만 경사 전담.
- **차선: 옵션 A(외부 발)** — '본체 100% 무변경·가역성' 최우선이면. 가장 안전.
- **옵션 C 비권장** — 결착 재설계 + 클리어런스 엉킴 + CNC 경사구멍 부담.

## 5. 결정 필요 (사용자)

1. **틸트 방식**: A(외부 발) / **B(쐐기 하판, 추천)** / C(쐐기 벽) / 보류.
2. **(B 채택 시) 쐐기 하판 제작법**: Weld-On 단차 적층(레이저컷 유지, 본딩 공정 추가) / 통짜 CNC(비권장).
3. **바텀갭 3.5mm**: 현행 유지(소켓 1.7mm 여유 OK) / 여유 확대(4~4.5mm, 스택 높이↑). ※ 틸트와 무관하게 별도 결정.
4. **각도**: 6도 확정(권장) / 조정(5~7도). 스펙에 프론트 끝 높이 병기 여부.
5. **반영 범위**: 지금 코드/뷰어/export까지 반영 / 문서로만 확정하고 코드는 추후.
6. **바텀갭 공유 부품**: USB 데몬/컨트롤러/배선을 소켓 없는 외곽에 배치 가능한지(1.0mm 데몬보드 필요 여부) — 컨트롤러 방식 미정과 연계.

> ※ 결정 전까지 코드(현행 v3)는 변경하지 않음.

## 6. 결론 — 폐기 (2026-06-25)

6° 틸트를 뷰어에 실제 적용해(쐐기 받침 + 내부 스택 6° 회전, Zen 65 옆 비교) 눈으로 확인한 결과, **틸트를 넣으니 케이스가 너무 커졌다.**

- 6° × 케이스 깊이 105.25mm → 뒤(숫자열)쪽이 **~11mm 높아짐**.
- 바닥을 책상에 평평하게 받치는 **쐐기 받침이 그 높이차만큼 부피·높이를 더해** 전체가 비대해짐. 컴팩트한 분리형 의도와 어긋남.
- 사용자 판단: **틸트 폐기, 평평한 v3 유지.**

코드는 틸트 변경 3파일(`dimensions.js`·`case-meshes.js`·`main.js`)을 커밋 `0bacbee` 상태로 원복함. 향후 필요 시 **본체 무변경**으로 외부 틸트 발(옵션 A)만 별도 제작해 분리 도입 가능.

## 7. 재도입 — FDM 7.5° 채택 (2026-07-07)

> §6 폐기는 **아크릴 평판 적층 + 쐐기 받침** 전제의 판단이었다. 65가 FDM(A1 mini) 제작으로 전환(`65/docs/fdm-m1-case.md`)되면서 전제가 바뀌어 재도입.

### 경위 (같은 세션 결정 흐름)

1. 사용자가 하판 AAA 홀더 수납을 검토 → 바텀갭 5.0으로 불가 → 8.0으로 확대 시험.
2. AAA(Ø10.5)는 8.0에도 불가 판명. 대신 **바텀갭을 솔더핀 하한(3.3)+여유 = 3.5로 내리고 틸트로 뒷높이를 얻는** 방향으로 전환.
3. Zen 65 실측(315×112, 옆면 앞 17.9/뒤 36 = 틸트 9.18°)을 레퍼런스로 렌더 비교(`reference-keyboard.js` 실측 보정) → **"Zen 높이만큼 허용" 기준으로 7.5° 확정, 앞행(스페이스바) 갭 3.5**.

### 확정 구조 = 옵션 신설 (A안, 사용자 스케치)

§3의 A(외부 발)/B(쐐기 하판)/C(쐐기 벽) 어느 것도 아닌 **FDM 전용 제4안**:

- 하판 base 평평 + **수직 지지 기둥·보스의 길이만 앞 짧고 뒤 길게** → 기둥 꼭대기가 7.5° 평면, 그 위에 PCB·plate·베젤이 통째로 기움. §2.3의 경고("PCB↔하판 갭에서 흡수 금지")는 **앞행 갭 3.5 고정 + 소켓 1.8 대비 1.7 여유**로 해소(솔더핀 3.3 전제면 앞행이 하한이므로 핫스왑 전제).
- CNC 경사가공 문제(§2.4)는 FDM이라 소멸. 레이저컷 제약 무관.
- 기하 정합(tiltY 투영 XY·경사면 컷·관통홀 확대 Ø5.4/Ø3.4)·PCB 외곽 개정은 `docs/PROCESS.md` §4.2 참조.

### 유지되는 판단

- 6°가 아니라 7.5°인 이유: Zen(9.18°)보다 완만하되 표준 범위(5~11°) 내, 사용자 지정.
- 배터리: AAA는 어떤 갭에서도 비현실적(Ø10.5) → 무선화 시 LiPo 파우치 재검토(§5-6 연계, 미결).
